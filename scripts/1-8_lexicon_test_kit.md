## 1. 감성 시드 사전 검수 결과 (`sentiment_seed.json`)

기존 사전을 실제 토큰화 로직(`tokenize()`)에 대입해서 검토해보니, **구조적인 빈틈**을 하나 발견했어요.

`tokenize()`는 문장 끝의 조사(이/가/을/를/은/는/도/만/에/로/의/요)만 제거하고, 동사/형용사 활용형(~았어/~었어, ~해)은 그대로 둬요. 그런데 사전에는 "서운", "속상", "외로", "답답", "불안" 같은 **어간만** 들어있어서, 실제 카톡에서 훨씬 많이 쓰이는 "서운해", "속상해", "외로워", "답답해", "불안해" 같은 형태는 **사전에 아예 안 걸려서 조용히 안 세져요.** 과거형("힘들었어", "화났어", "짜증났어" 등)도 마찬가지 문제예요.

즉, 지금 상태로는 "내 단어" 카드가 실제 대화에서 이 감정 단어들을 상당수 놓치고 있을 가능성이 커요. 감성사전이 검증 안 됐다는 설계 노트 ②의 우려가 사실 이런 형태로도 나타날 수 있었던 거예요.

**보강안**: `sentiment_seed_v2_draft.md`(아래 함께 보냄)에 이 빈틈을 메운 버전을 만들어뒀어요. "해"/"~았어/었어" 변형을 canonical로 묶어 추가했고, "존예", "존잘", "꿀잼", "다행", "감동", "뿌듯", "미안해", "삐졌어", "질투", "무서워", "지겨워" 같이 커플 대화에서 흔한데 아예 없던 단어도 몇 개 추가했어요.

**확인해주실 것**: 새로 추가한 단어들이 실제 커플 대화 톤에 맞는지, 빼고 싶은 게 있는지 한 번 훑어봐 주세요. 이건 취향/맥락 판단이라 제가 임의로 최종본에 반영하지 않고 초안(`data/knowledge/sentiment_seed_v2_draft.json`)으로 따로 저장해뒀어요. 괜찮다 싶으면 그대로 `sentiment_seed.json`에 덮어쓰시면 됩니다.

## 2. lexicon.md 초안 (Phase 3 `build_lexicon` 프롬프트)

지금 `prompts/lexicon.md`는 계약만 있고 지시문 본문이 "TODO: 윤아"로 비어 있어요. interpret.md 때와 똑같은 상황이라, 같은 방식으로 초안을 써서 아래에 넣었어요.

```
너는 커플이 실제로 주고받은 카톡 대화에서, 사전에 없는 단어의 감성(긍정/부정/중립/제외)을
판단하는 역할이야. 아래 규칙을 지켜서 분류해줘.

[입력]
100개 단어의 목록. 각 단어마다 그 단어가 처음 등장한 대화 3건의 앞뒤 2~3토큰 예시가 같이 주어진다.

[출력 형식 — 반드시 JSON]
[
  {"term": "원래 단어", "canonical": "대표형", "polarity": "pos|neg|neutral|exclude"},
  ...
]

[규칙 — 반드시 지킬 것]
1. canonical은 같은 단어의 철자 변형만 묶는다 (예: "조아"→"좋아", "짱나"→"짜증").
   뜻이 비슷한 다른 단어(동의어)는 절대 묶지 않는다 (예: "좋아"와 "행복"은 별개 단어).
2. polarity는 예시 문맥을 보고 판단한다. 겉으로 부정적인 단어("바보", "밉다", "죽겠어")라도
   앞뒤 문맥이 애정 표현(장난스러운 놀림, 다정한 뉘앙스)이면 pos로 판단한다.
   문맥만으로 판단이 애매하면 억지로 pos/neg를 정하지 말고 neutral로 분류한다.
3. exclude는 다음에 해당할 때만 쓴다: 욕설·비속어, 사람 이름이나 호칭(별명 포함).
   호칭에는 실제 이름("민준아")뿐 아니라 **상대를 부르는 2인칭 호칭도 포함**된다
   (예: "자기야", "자기", "오빠야", "여보", "애기야", "자기얌" 등). 이런 호칭은 표면적으로
   다정하게 들려도 감성을 나타내는 단어가 아니라 "부르는 말"이므로 pos로 분류하지 말고 exclude로 분류한다.
   전화번호·생년월일 등 식별 가능한 개인정보도 exclude. 감성이 없는 일반 명사(예: "치킨", "회사")도 exclude.
4. 판단이 애매한 단어를 pos/neg로 추측해서 단정하지 않는다 — 애매하면 neutral을 우선한다.
   특히 예시가 1건뿐이거나 문맥이 부족하면 neutral로 분류하는 쪽을 택한다.
5. 모든 출력(canonical 포함)은 한국어로 쓴다.

JSON 배열 외의 다른 텍스트(설명, 인사말)는 출력하지 않는다.
```

- 전체 오분류율 = (틀린 개수) / 18
- **반어적 애정표현 구간(5개)의 오분류율이 30~40%를 넘으면** → 설계 노트 ②의 기준대로 이 카드는 cut 검토 (완화책부터 시도: 신뢰도 임계값, 자동 대신 사용자 등록형)
