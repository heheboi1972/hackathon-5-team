**1차 관찰**:
- 숫자 지어내기 0/10, 사람 비교 0/10, interpretations 종결어미 위반 0/10 — 내용 규칙은 매우 안정적
- 근거·지식 후보가 없을 때(4, 8) 지어내지 않고 정직하게 빈 배열 처리 — 환각 방지 잘 지켜짐
- evidence/sources를 후보 객체 그대로 안 쓰고 문자열로 축약한 경우 4/10 (3, 5, 9, 10)

## 최종 결론

**대안 모델 필요 여부: 아니오.** 내용 품질(관찰·해석 문장의 자연스러움, 규칙 준수, 톤, 환각 방지)은 모델 자체로 충분히 좋음. gpt-oss를 다른 모델로 바꿀 이유는 없어 보임.

**단, 프롬프트만으로는 형식을 100% 보장 못 함.** 10/10 중 9/10까지는 프롬프트 보강으로 끌어올렸지만 마지막 1개가 계속 깨짐 → **코드 레벨 방어 로직을 같이 넣는 걸 권장**:
- API 응답을 파싱할 때 `evidence`/`sources` 항목이 문자열이면, 원본 `evidence_candidates`/`knowledge`에서 해당 문자열(snippet 또는 doc명)을 검색해서 객체로 재구성하는 후처리 함수를 추가
- 재구성도 실패하면(매칭되는 후보를 못 찾으면) 해당 항목을 버리거나 카드 자체를 안전하게 숨김 처리

**다음 반영할 곳**: `interpret.md`의 "## 지시문"에 2차 개정 프롬프트(evidence/sources 객체 유지 규칙 포함)를 최종본으로 채우고, `ai_service.py` 또는 응답 파싱 단계에 위 방어 로직 추가를 팀(윤석/형준)에게 공유.
